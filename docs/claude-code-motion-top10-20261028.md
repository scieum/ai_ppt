## 영상별 분석

아래의 “강의 설명”과 노션톡 예시는 원문의 직역·재현이 아니라 이번 웨비나를 위한 자체 제안이다.

### 1. 설명 영상에도 모션 그래픽이 들어간다

**확인한 내용**: Claude의 일반 채팅과 Code 작업 영역을 구별하고 Code에서 진행한다고 설명한다. 말하는 영상 위에 자막·박스·보조 화면을 얹는 사례와 뒤쪽의 입체 설명 영상 사례를 다룬다.

**강의 설명**: 모션 그래픽은 화면 전체를 채우는 애니메이션 외에도, 말하는 사람 옆의 숫자나 설명 그림으로 쓰인다.

**노션톡 자체 예시**: 노션톡 인물 한 명 옆에 “무료 웨비나” 글자와 작은 일정 카드가 등장하는 자체 도식. 영상 속 임금·부동산·우주 사실을 그대로 옮기지 않는다.

**반영 위치**: 유형 장표의 “설명 영상·UI” 설명에 합치기. 별도 설치·하드웨어 설명은 생략.

근거 구간: [01:15–03:20](https://www.youtube.com/watch?v=hffQ4UleKUU&t=75s), [20:00–21:40](https://www.youtube.com/watch?v=hffQ4UleKUU&t=1200s).

### 2. 쉬운 예시를 가장 많이 가져올 수 있는 영상

**확인한 내용**: 숫자가 증가하다 마지막 값에 머무는 카운트업, 카드의 순차 등장, 글자가 입력되는 검색창, 문장의 특정 구간을 따라가는 강조, 도시 사이를 잇는 지도 경로를 나누어 보여 준다. Code와 Remotion 사용은 04:44 이후 구간에서 확인된다.

**강의 설명**: 숫자·목록·검색창처럼 익숙한 화면도 값·등장 순서·강조 위치가 시간에 따라 변하면 모션 그래픽이 된다.

**노션톡 자체 예시**: 0→50→100의 가상 숫자, “개념 / 종류 / 효과” 세 카드, “노션톡” 검색창. 원문의 통화·문장·지도 디자인 대신 자체 자료를 사용한다.

**반영 위치**: 여섯 사례를 각각 한 장씩 늘리지 말고 “숫자와 목록 / 검색과 강조 / 지도와 레이어” 세 묶음으로 재구성.

### 3. 영상 속 요소는 서로 다른 일을 한다

**확인한 내용**: 실사 편집, 애니메이션, 보조 자료, 소리, 최종 합성을 역할별로 구분한다. Code가 전체를 연결하고 Hyperframes가 그래픽을 맡는 혼합 편집 사례다. 후반에는 등장 시점·음향을 검토하며 수정하는 모습이 설명된다.

**강의 설명**: 인물 영상은 이야기하고, 화면의 그래픽은 핵심을 보이며, 소리는 박자를 더한다.

**노션톡 자체 예시**: 같은 노션톡 설명 화면을 배경 / 글자·도형 / 소리의 세 층으로 나누는 도식. 소리가 없는 예시는 무음이라고 표시한다.

**반영 위치**: 기존 박자 장표와 연결. 원문의 도구 일곱 개를 그대로 목차로 만들지 않는다.

### 4. 참고 자료와 일관성의 기준을 구별한다

**확인한 내용**: 이미지·링크·영상 참고를 함께 사용하는 사례와 실제 로고·제품 화면을 쓰는 사례를 구분한다. 후반에는 음악·효과음·화면 움직임이 맞물리는 예시를 설명한다.

**강의 설명**: 이미지는 색·글자·모양을 보여 주고, 영상은 움직이는 속도와 전환을 보여 준다. 로고와 캐릭터의 정체성은 유지할 수 있다.

**노션톡 자체 예시**: 주황 계열과 노션톡 삼인방은 고정하고, 등장 순서·박자만 비교하는 자체 예시. 다른 브랜드의 화면·카피·캐릭터는 옮기지 않는다.

**반영 위치**: 기존 레퍼런스·박자 장표의 설명에 통합. 상세 하네스·복제 음성·긴 디렉터 지시는 제외.

### 5. 목록·형광펜·경로는 정보를 따라 움직인다

**확인한 내용**: 숫자 카운터, 세로로 쌓이는 설명 박스, 본문 강조, 지도상의 이동을 한 영상에 배치한다. 07:06 이후 Code와 Remotion 구간을 분리해 설명하며 투명 배경 합성도 다룬다.

**강의 설명**: 한꺼번에 등장하는 목록과 차례로 등장하는 목록은 같은 내용을 다른 순서로 보게 한다. 지도에서는 선과 카메라가 이동을 나타낸다.

**노션톡 자체 예시**: “기본 지식 / 레퍼런스 / 미리 확인” 카드가 차례로 나타나는 예시. 강조 문장은 자체 문장으로 대체한다.

**반영 위치**: 2위와 중복되므로 한 묶음으로 합친다. LUT·SRT·설치·내보내기 조작은 생략.

### 6. 글자·도형·시간을 따로 바꿀 수 있다

**확인한 내용**: 앞부분은 일반 Claude Motion의 글자·색·시간 수정 사례이고, 09:05 이후는 Code·Remotion 대안이다. Code 예시에서는 종이 형태의 시계탑이 로켓으로 변하는 모핑을 소개한다. 두 환경을 같은 기능으로 단정하지 않는다.

**강의 설명**: 모션 그래픽은 여러 요소로 구성된다. 글자 하나의 변화, 형태의 변화, 장면 길이의 변화는 서로 다르다.

**노션톡 자체 예시**: 원·말풍선·화살표 등 자체 도형의 형태 변화를 기존 모핑 설명에 연결한다. 시계탑·로켓 장면은 복제하지 않는다.

**반영 위치**: 기존 속성·모핑에 통합. 서비스별 버튼·요금·권한 설명은 넣지 않는다.

**확인한 내용**: 일반 Claude Design과 Code·Hyperframes 방식을 구별한다. 말의 단어별 시점과 그래픽을 맞추는 예시가 있으며 후반 수정 과정에서는 잘린 숫자와 흐린 제목이 반복해서 발견된다.

**강의 설명**: 그래픽이 제때 나와도 글자가 잘리거나 흐리면 전달이 어렵다. 등장 타이밍과 화면의 읽힘은 따로 관찰할 수 있다.

**노션톡 자체 예시**: “100”이 들어갈 때 잘린 경우와 전체가 보이는 경우를 같은 위치·크기로 비교. 프롬프트 예시로 전환하지 않는다.

**반영 위치**: 시간 장표에는 “언제 등장하는가”, 수정 장표에는 “무엇이 잘렸는가” 설명을 나눠 연결.

### 8. 말하는 순간과 그래픽이 만나는 지점

**확인한 내용**: Code가 연결하고 Hyperframes가 카드·자막을 얹는 시연이다. 같은 말에 맞춰 그래픽이 등장하며, 검토에서는 얼굴을 가리는 카드와 불필요한 격자가 수정 대상으로 등장한다. 도구별 결과 비교는 발표자의 취향으로 설명된다.

**강의 설명**: 내레이션과 그래픽은 같은 내용을 서로 다른 방식으로 전달한다. 그래픽은 인물과 함께 놓이므로 앞뒤의 관계도 생긴다.

**노션톡 자체 예시**: 노션톡 인물 옆 카드와 인물을 가린 카드를 비교하는 자체 화면. 카드의 등장 시점은 동일하게 둔다.

**반영 위치**: “박자”와 “레이어” 설명에 연결. 특정 도구가 항상 우수하다는 결론은 채택하지 않는다.

### 9. 한 화면에도 별도 요소가 겹쳐 있다

**확인한 내용**: 일반 Motion, Code 사용 언급, 외부 생성 영상을 혼합한다. 글자·색·레이어·장면 길이를 바꾸는 사례와, 생성된 캐릭터 장면에 코드로 된 페이지·문자·경로를 결합하는 설명이 나온다.

**강의 설명**: 배경·캐릭터·글자·선은 한 장의 그림처럼 보여도 서로 다른 층으로 움직일 수 있다.

**노션톡 자체 예시**: 새 캐릭터를 늘리지 않고 기존 삼인방 자산 중 한 포즈와 자체 글자·도형만 분리해 보여 준다.

**반영 위치**: 레이어 개념만 간단히 사용. 3D 제작·외부 모델·전문 편집기 전송은 제외.

### 10. 글자와 도형도 설명의 주인공이 된다

**확인한 내용**: 제품 UI·키네틱 타이포그래피·모델 비교 도식과 외부 자산을 합친 설명 영상을 예로 든다. Code와 Remotion 방식 이후 외부 생성·내레이션을 더하는 구조로 확장한다.

**강의 설명**: 타이포그래피는 글자, UI 모션은 인터페이스, 인포그래픽은 숫자와 관계를 주로 움직인다.

**반영 위치**: 기존 종류 설명과 겹치므로 보충 멘트로 합친다. MCP 설치·모델 비교·비용·자동 성공 주장은 생략.

## 추가할 내용은 세 묶음으로 정리

기존 종류·효과·타이밍을 다시 설명하는 장표를 늘리지 않고, 다음 세 묶음 안에서 쉬운 실제 사례를 연결한다. **아래 세 장은 기획 후보이며 현재 26장 PPT에 추가된 것으로 표시하지 않는다.**

### A. 숫자와 목록이 움직이는 방법

- 핵심 설명: 숫자가 증가하는 **카운트업**과 항목이 차례로 등장하는 **순차 등장**은 정보의 순서를 눈으로 보이게 한다.
- 예시: 가상 숫자 `0 / 50 / 100`의 세 상태와 “개념 / 종류 / 효과” 카드 세 개. 마지막 숫자는 잠시 머무르게 표현한다.
- 연결: 26장 기준 8쪽 “다섯 종류”, 13쪽 “리빌·타이프라이터·순차 등장”. 기존 순차 등장의 정의를 반복하지 않고 목록 예시를 보충한다.
- 디자인: L12 두 패널 또는 기존 세 카드. 검정·흰색·주황, 편집 가능한 자체 글자·도형.
- 원고: “숫자는 결과를 보여 주고, 움직이는 숫자는 값이 바뀌는 과정을 보여 줍니다. 목록의 시작 시점도 서로 다를 수 있습니다.”

### B. 검색창과 문장 강조도 모션 그래픽이다

- 핵심 설명: 검색어가 입력되는 **타이프라이터**, 강조 면이 펼쳐지는 **리빌**은 익숙한 인터페이스와 문장에서도 보인다.
- 예시: 검색창의 “노션톡” 세 글자, “오늘은 모션 그래픽을 이해합니다” 중 “모션 그래픽” 아래로 펼쳐지는 주황 강조. 실제 앱 캡처로 위장하지 않는다.
- 연결: 13쪽의 두 효과 설명에 같은 화면을 두 상태로 보여 주는 예시를 보충할 수 있다.
- 디자인: L12 같은 폭의 두 패널. 캐릭터 장식 없이 검색창과 문장만 배치.
- 원고: “글자가 입력되는 움직임과 강조가 퍼지는 움직임은 다릅니다. 앞의 효과 이름을 익숙한 화면에서 찾아보면 쉽게 구별됩니다.”

### C. 지도 경로와 겹쳐진 화면의 움직임

- 핵심 설명: 선이 그려지는 **경로 리빌**, 시점이 따라가는 **카메라 이동**, 앞뒤 요소가 겹치는 **레이어**를 구별한다.
- 예시: 실제 지도의 복잡한 데이터 없이 “시작 / 도착” 두 점을 잇는 자체 선. 옆에는 배경·노션톡 한 포즈·설명 글자의 세 층을 나란히 분해한다.
- 연결: 15쪽 “장면을 잇는 움직임”과 20쪽 “레퍼런스의 역할”. 기존 패럴랙스 설명에는 앞뒤 층의 관계만 더한다.
- 디자인: L07 대조 행 또는 L12 두 패널. 설명용 도식에는 직접 만든 선과 도형을 사용하며 장식 이미지를 늘리지 않는다.
- 원고: “지도에서는 선이 이동 경로를 보여 주고, 화면의 시점이 그 선을 따라갈 수 있습니다. 인물 위 설명 글자처럼 여러 층이 함께 보이기도 합니다.”

위 A·B는 [Matt Loui](https://www.youtube.com/watch?v=8oIFBQ9BhVU)와 [Sanji Nai-Chien](https://www.youtube.com/watch?v=j4FzO2fF1kg)의 공통 사례를 묶은 자체 교육안이다. C의 레이어 설명은 [Higgsfield AI](https://www.youtube.com/watch?v=5HYYXYYCrL4)·[Nate Herk](https://www.youtube.com/watch?v=Aw3BkmhYu4I)의 합성 사례를 기초 개념으로 바꾼 제안이다.
