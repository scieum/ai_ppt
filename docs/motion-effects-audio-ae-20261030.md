## 1. 이번 자료에서 가져올 핵심

- **움직임의 어휘를 넓힌다.** 단순히 나타나고 이동하는 것에서 더 나아가, 살짝 지나쳤다가 멈추기·흐림에서 선명해지기·숫자 굴리기·눌렸다 늘어나기를 설명한다.
- **화면과 소리의 역할을 연결한다.** 글자가 멈추는 순간, 카드가 뒤집히는 순간처럼 움직임의 특징이 드러나는 지점에 소리를 연결하는 예시를 제안한다.
- **이미지를 움직일 요소로 이해한다.** AE 사례는 완성 이미지를 그대로 흔드는 방식과, 글자·도형·배경을 편집 가능한 요소로 재구성해 움직이는 방식을 구분할 때 유용하다.

기존 흐름인 ‘기본 지식 → 이미지·영상 레퍼런스 → storyline.md와 스틸컷 두 장 확인 → 수정 후 제작’에 연결한다. 설치·긴 프롬프트·앱 조작 설명으로 확장하지 않는다.

## 2. 여덟 가지 모션 — 이름보다 움직임을 먼저 보여주기

근거: 사용자 제공 @mynameisjaemin 게시물 캡처. 게시물의 전체 영상은 재생·분석하지 않았으며, 캡처에 보이는 설명을 해석했다. 오른쪽 예시는 자체 구성안이다.

| 효과 이름 | 눈으로 보면 어떻게 움직이나 | 노션톡용 예시 |
|---|---|---|
| 스냅 텍스트 / Snap text | 글자가 빠르게 들어와 도착점을 조금 지나친 다음 제자리로 돌아와 멈춘다. | ‘노션톡’이 들어와 살짝 튕긴 뒤, ‘웨비나 챌린지’가 이어서 등장한다. |
| 스태거 / Stagger | 여러 요소가 동시에 시작하지 않고 조금씩 시간차를 두고 같은 움직임을 한다. | 세 개의 활동 카드가 하나씩 올라와 자리를 잡는다. |
| 블러 인 / Blur in | 흐릿한 글자가 선명해진다. 캡처 예시는 크기와 회전도 함께 바뀌며 정렬된다. | 흐릿하고 흩어진 ‘새로운 시작’이 읽을 수 있는 한 줄로 모인다. |
| 마스크 리빌 / Mask reveal | 가려진 영역이 열리면서 이미지나 글자가 점차 드러난다. 대상 자체가 이동하지 않아도 된다. | 가림막이 옆으로 걷히면서 주황색 제목이 나타난다. |
| 카운터 / Counter | 숫자가 목표값까지 바뀐다. 캡처는 각 자릿수가 굴러가는 형태다. | 설명용 가상 수치 ‘진행률 0% → 100%’가 올라간다. |
| 모핑 / Morphing | 하나의 형태가 다른 형태로 이어서 바뀐다. 크기·모서리·색 등이 함께 변할 수 있다. | 작은 둥근 알림이 넓은 안내 카드로 변한다. |
| 스쿼시 앤 스트레치 / Squash & stretch | 눌려 납작해졌다가 길게 늘어나며 탄성과 속도감을 만든다. | 공이 바닥에 닿아 납작해지고, 다시 튀어 오르며 길어진다. |
| 카드 플립 / Card flip | 카드가 축을 중심으로 돌아가며 앞면과 뒷면이 바뀐다. | 앞면의 질문 카드가 돌아가 뒷면의 답을 보여준다. |

### 설명할 때 구분할 점

- **모션 그래픽의 종류와 효과는 다른 분류다.** 타이포그래피·인포그래픽은 무엇을 보여주는지에 가깝고, 스태거·리빌·플립은 어떻게 움직이는지에 가깝다. 타이포그래피 한 장면에도 여러 효과가 함께 쓰일 수 있다.
- 스냅 텍스트나 블러 인은 여러 속성을 묶은 표현일 수 있다. 모든 앱에 같은 이름의 버튼이나 프리셋이 있다는 뜻은 아니다.
- 스태거는 새로운 모양이 아니라 **시작 시점의 차이**다. 기존 딜레이 설명과 연결한다.
- 마스크 리빌은 ‘가림 영역이 바뀌는 것’, 슬라이드는 ‘대상의 위치가 바뀌는 것’으로 대비하면 쉽다.
- 카운터는 숫자 변화 자체를 보여주며, 실제 데이터가 없는 설명 예시는 가상 수치로 표시한다.
- 카드가 180° 돌면 반대 면을 보고, 360° 돌면 처음 면으로 돌아온다. 캡처의 한 바퀴 회전과 우리 예시의 앞뒤 전환을 구분한다.

캡처에 적힌 0.8초·100ms·회전 각도 등은 해당 예시의 설정값이다. 보편적인 정답이나 필수 규칙으로 소개하지 않는다. `natural`, `smooth`, `slowdown` 같은 표기도 도구 공통 표준 이징 이름으로 취급하지 않는다.

**장표 하단 결론 바 제안:** ‘효과 이름과 함께 시작 모습·변화·멈춘 모습을 봅니다.’

## 3. 효과음 — 찾기·배치하기·합성하고 분석하기

사용자 제공 @rebornlabs.ai 캡처의 세 도구를 공식 자료와 대조했다. 세 도구는 같은 기능을 하는 대체재가 아니며, 항상 전부 순서대로 사용할 필요도 없다.

| 도구 | 쉽게 설명한 역할 | 구분할 사항 |
|---|---|---|
| Openverse | 이미 공개된 오디오를 **검색**한다. | 효과음 생성기가 아니다. 음악 등도 검색되므로 결과를 확인한다. |
| Clipwing Real SFX | 사용할 수 있는 녹음 효과음을 영상의 지점에 **배치**하는 Claude Code 스킬이다. | 직접 새 소리를 합성하는 도구가 아니다. |
| Leonxlnx/earshot | 소리를 **분석·비교**하고, 코드 기반 효과음을 **합성**할 수 있다. | ‘자동 분석 통과’가 사람이 듣기에 좋은 결과라는 보장은 아니다. |

### Openverse: 필요한 소리 찾기

오디오 검색 결과에서 원출처·제작자·라이선스 정보를 확인할 수 있다. 검색된 파일마다 이용 조건이 다르며, Openverse 자체도 원본에서 권리를 확인하도록 안내한다. 캡처의 특정 날짜 오디오 수량은 현재 효과음 수량으로 인용하지 않는다. [공식 API](https://api.openverse.org/v1/), [이용 조건](https://docs.openverse.org/terms_of_service.html)

### Real SFX: 가지고 있는 소리를 장면에 맞추기

공식 설명에 따르면 사용자의 효과음 라이브러리와 큐 목록·타임라인·영상 정보를 이용한다. MP4, 별도 WAV 효과음 트랙, 배치 보고서를 출력한다. Python 3.9 이상과 FFmpeg 등 실행 환경이 필요하므로 웹사이트를 열기만 하면 바로 쓰는 서비스로 소개하지 않는다. 공식 페이지의 기본 음원 포함 여부 안내가 혼재하므로 풍부한 무료 음원 라이브러리가 전부 포함된다고 설명하지 않는다. [Clipwing 공식 안내](https://clipwing.pro/skills/real-sfx)

### earshot: 소리의 특징을 분석하고 필요한 효과 합성하기

공식 저장소는 로컬 CLI·Python API·MCP 연결, 소리 묘사·후보 비교·영상 소리 분석, 코드 기반 합성 기능을 설명한다. 코드의 MIT 라이선스와 사용 음원·모델의 조건은 구분한다. 이름이 비슷한 다른 저장소가 있으므로 **Leonxlnx/earshot** 링크를 사용한다. 이번 조사에서 직접 설치하거나 출력 품질을 청취 검증하지 않았다. [공식 저장소](https://github.com/Leonxlnx/earshot)

### 웨비나에서 보여줄 쉬운 소리 예시 — 자체 제안

| 화면에서 일어난 일 | 연결해 볼 소리 | 전달하려는 느낌 |
|---|---|---|
| 제목이 도착해 멈춤 | 짧고 가벼운 탭 또는 팝 | 여기서 제목이 완성됐다는 구분 |
| 카드가 옆으로 넘어감 | 짧은 스윽 소리 | 방향과 전환 |
| 진행률이 끝에 도달함 | 짧은 알림음 한 번 | 완료 |
| 중요한 숫자가 강조됨 | 가벼운 타격음 | 강조 시점 |

먼저 같은 장면의 무음 버전과 소리를 붙인 버전을 비교하는 구성이 적합하다. 모든 글자에 효과음을 붙이는 예시보다는 중요한 두세 순간만 비교한다. 내레이션·배경음악·효과음은 역할이 다르므로, 이후 내레이션 설명과도 구분해서 연결한다. 위 표는 도구의 실측 결과가 아니라 자체 제작 후보다.

캡처의 ‘전부 무료’는 장표 문구로 그대로 옮기지 않는다. 도구 배포, AI 계정 이용, 음원 이용 조건은 각각 확인해야 한다.

**장표 하단 결론 바 제안:** ‘소리는 움직임의 중요한 순간을 더 또렷하게 만듭니다.’

## 4. 이미지 한 장에서 AE 모션으로 — 선택 심화 사례

출처: 오디씨 LAB, [JPG 한 장으로 AE 모션그래픽](https://odssilab.com/recipes/ae-motion/). 웹페이지 본문과 공개된 안내 내용을 읽었으며, 포함된 시연 영상을 직접 재생하거나 같은 결과를 재현한 것은 아니다.

이 사례의 핵심은 이미지를 잘라 붙이는 대신, 그림을 참고해 글자·도형·배경 등 **편집할 수 있는 AE 레이어로 재구성**하는 데 있다. 정지 화면을 먼저 확인하고 움직임을 더하는 흐름이다.

1. 이미지에서 움직일 요소를 구분한다.
2. 요소를 편집 가능한 레이어로 재구성한다.
3. 정지 화면의 구성과 형태를 확인·수정한다.
4. 요소별 움직임을 추가하고 미리보기로 확인한다.

이 흐름은 우리 웨비나의 ‘스틸컷 먼저 확인’과 연결할 수 있다. 다만 원본 사례의 실제 AE 실행은 스크립트와 별도 환경을 사용하는 방식이다. **작성자는 Mac에서 확인했으며 Windows는 미검증으로 안내한다.** 참가자 모두가 그대로 실행할 수 있다고 소개하거나 AE를 공통 필수 준비물에 추가하지 않는다.

### 우리 자료에 가져올 표현 — 자체 구성

노션톡 이미지 한 장을 왼쪽에 놓고, 오른쪽에는 ‘제목 / 캐릭터 / 배경’으로 나눈 설명 그림을 배치한다. 다음 단계에서 각 요소가 다른 시간에 움직일 수 있음을 보여준다. 이것은 개념 설명용 도식이며 JPG에 원래 편집 가능한 레이어가 들어 있다는 뜻이 아니다.

원문 예시의 일치도 요구 문구를 그대로 복사하지 않고, 사용 권한이 있는 노션톡 자산의 구성 원리를 설명하는 방식으로 재구성한다. 래스터 이미지를 레이어로 재구성하는 과정에서 원본과 차이가 생길 수 있다.

원문의 `CLAUDE.md`는 작업 규칙을 담는 파일로 소개된다. 우리 강의의 `design.md`, `motion.md` 등과 이름·자동 참조 동작이 같다고 설명하지 않는다. **우리 기준 문서는 작업할 때 명시적으로 함께 제공하는 자료**라는 기존 설명을 유지한다.

**장표 하단 결론 바 제안:** ‘이미지의 구성을 먼저 확인하고, 요소별로 움직임을 더합니다.’

- 검정·주황·흰색, 현재 폰트·상단·브랜드·푸터를 유지한다.
- 모션 장표는 움직이는 예시 두 개와 짧은 설명으로 구성한다. 멈춘 이미지 한 장으로 효과를 설명했다고 처리하지 않는다.
- 결론이 있는 장표에는 사용자가 지정한 **왼쪽 라벨 + 긴 어두운 본문 텍스트 바**를 쓴다.
- 도구 역할은 세 카드, 이미지 해석은 요소 분리 그림, 음향은 같은 장면의 전후 비교가 적합하다.
- 캡처의 캐릭터·문구·레이아웃을 그대로 복제하지 않는다. 노션톡 자산은 이해에 필요한 곳에서만 사용한다.
