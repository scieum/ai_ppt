## 1. 이번 파트의 목표와 디자인 기준

### 상단 번호는 관련 내용의 묶음

장표가 늘어도 같은 개념 묶음에서는 번호를 유지한다. 번호 옆에 소제목을 붙여 세부 내용을 구분한다. 장표를 합치거나 본문을 줄이기 위한 규칙이 아니다.

| 표기 | 묶음 | 22장 PPT의 페이지 |
|---|---|---|
| 01 | 모션 그래픽 이해하기: 뜻·표현 유형 | 4~6쪽 |
| 02 | 움직임과 효과: 기본 속성·등장·글자·시간·요청 문장 | 7~11쪽 |
| 03 | 제작 예제: 비교·타이포그래피·웹사이트·원자모형 | 12~18쪽 |
| 04 | 내 수업에 적용하기 | 19쪽 |

‘02 움직임과 효과 · 시간과 속도’처럼 표시한다. 실제 페이지와 전체 계획의 장표 번호는 별도로 유지한다. 최신 파일은 번호 체계를 반영한 v2다.

모션 그래픽의 뜻·표현 유형·기본 속성·효과 이름·시간과 속도를 먼저 이해한 뒤, **노션톡 홍보 타이포그래피 → 실제 웹사이트 소개 → 원자모형 변천 설명**의 세 사례를 경험한다. 참가자는 세 개를 모두 만드는 대신 자기 수업에 맞는 하나를 선택해 첫 요청을 보내거나 관찰 기록을 남긴다. 마지막에는 결과에서 고칠 조건 하나를 구체적인 문장으로 적는다.

기존 대표 5장 `output/webinar-samples/NotionTalk_모션그래픽_주황포인트_자체사례_v5.pptx`의 디자인을 유지한다. 주황 그라데이션 표지·세 캐릭터·상단 안내·제목·카드·문서 표·흰 프롬프트 박스·로고·푸터·서체·간격을 보존한다. 이전 9장 추가본 `output/webinar-part01-added/NotionTalk_대표5장유지_Part0_Part1추가_9장_v2.pptx`는 보존하고 실제 반영본은 별도 15장 파일로 저장했다.

향후 장표 제작도 해당 유형의 내용 슬롯 안에서 진행한다. 거부된 `webinar-three-cases-v2`의 새 5장이나 입력창 조각을 확대했던 UI 안내 자료를 후속 디자인 기준으로 사용하지 않는다. 기준 해시는 [디자인 기준 기록](checks/design-baseline.json)에 있다. 디자인 보존과 G10 검토 상태는 별개이며, 검토 완료나 승인 증빙을 생성하지 않는다.

Part 0에서는 **“코덱스 or 클로드 유료 요금제”**를 안내한다. 둘 중 하나의 유료 계정이 필수이며, 힉스필드는 있으면 실습하고 없으면 시연을 본다. 로그인·저장 위치 안내는 [Part 0](part-0.md)에서 마친다.

## 기초 이해 — 10분

### 모션 그래픽의 뜻

글자·도형·이미지 같은 디자인 요소에 움직임을 더해 정보를 전달하는 시각 표현이다. 정지 디자인과 같은 글자가 시간에 따라 등장하는 예시를 비교한다. 애니메이션은 더 넓은 범주다. AI 도구를 먼저 열기 전에 무엇을 만들려는지 이해한다.

### 영상의 표현 유형

| 표현 유형 | 중심 요소 | 수업 적용 예 |
|---|---|---|
| 키네틱 타이포그래피 | 움직이는 글자와 문장 | 핵심어·질문·노션톡 홍보 |
| 인포그래픽 | 수치·관계·과정 | 원자모형의 차이·개념 비교 |
| UI·서비스 소개 | 화면·기능과 쓰임 | Notion 문서 소개 |
| 로고·타이틀 | 브랜드·영상의 시작 | 강의 오프닝 |
| 일러스트·캐릭터 | 그림·인물의 동작 | 상황·과학사 설명 |

여러 표현을 조합할 수 있는 실용적 분류다. 과학사는 설명 주제, 웹사이트 URL은 입력 방식이므로 유형과 구분한다.

### 기본 변화와 효과 이름

위치(Position)·크기(Scale)·각도(Rotation)·불투명도(Opacity)는 바꿀 속성이다. 다음 효과는 이 속성과 보이는 영역·글자 단위를 조합해 만든다.

| 이름 | 화면에서 보이는 변화 | 쉬운 요청 예 |
|---|---|---|
| 페이드 인·아웃, Fade | 서서히 나타나거나 사라짐 | 제목을 천천히 나타내 줘 |
| 슬라이드 인, Slide In | 화면 밖에서 안으로 이동 | 글자가 왼쪽에서 들어오게 해 줘 |
| 줌·스케일, Zoom/Scale | 크기가 커지거나 작아짐 | 핵심어를 작게 시작해 크게 보여 줘 |
| 와이프·리빌, Wipe/Reveal | 가려진 부분이 열려 보임 | 제목이 왼쪽부터 드러나게 해 줘 |
| 타이프라이터, Typewriter | 글자가 하나씩 표시됨 | 문장을 한 글자씩 나타내 줘 |
| 순차 등장, Stagger | 여러 요소가 간격을 두고 등장 | 세 단어를 0.15초 간격으로 보여 줘 |

순차 등장은 시작 간격을 주는 규칙이며 모든 도구에서 하나의 효과 메뉴로 제공되는 것은 아니다. 리빌은 넓은 드러내기 표현이고 마스크 리빌은 영역을 사용하는 구현 방식이다. 회전도 기본 속성 변화로 보여 주되 장면마다 모든 효과를 쓰게 하지 않는다.

### 시간과 속도

지속 시간은 움직임에 걸리는 시간, 지연은 시작 전 기다리는 시간이다. 이징(Easing)은 움직이는 동안 속도가 달라지는 방식이다. 이즈 인은 천천히 시작하고, 이즈 아웃은 끝에서 느려진다. 읽는 유지 시간은 이동 시간과 별도로 확보한다. 키프레임은 특정 시점의 상태를 정하는 기준점으로만 짧게 소개하며 편집기 조작은 뒤로 넘긴다.

기초의 마무리 요청 예: “제목을 왼쪽에서 0.8초 동안 슬라이드 인 하고 끝에서 천천히 멈추게 해 줘. 세 핵심어는 0.15초 간격으로 페이드 인 하고, 모두 나온 뒤 3초 동안 읽을 수 있게 유지해 줘.” 수치는 비교용 예시다. 이 요청을 외우게 하지 않고 필요한 변화 하나를 골라 말하게 한다.

## 4. 사례 A — 노션톡 홍보 타이포그래피, 20초

**질문:** 글자가 움직이는 것과 정보가 잘 읽히는 것은 어떻게 다를까?

먼저 예시를 재생하고, 입력은 홍보 문장과 행사 정보라는 점을 짚는다. 복잡한 장면표·전문 용어·외부 커넥터 없이 시작한다.

### 시작 요청

```text
‘수업 자료가 영상이 되는 순간’으로 시작하는 노션톡 무료 웨비나 홍보
타이포그래피 영상을 20초로 만들어 줘. 글자가 차례로 이어지고 핵심어가
강조되게 해 줘. 검정 바탕에 주황색 포인트를 써 줘.
마지막에는 ‘2026년 11월 1일 일요일 저녁 8시’와
‘댓글에 노션톡을 남겨 주세요’를 넣어 줘.
지금 환경에서 재생할 수 있는 결과로 보여 줘.
```

이 문구를 장표에 실을 때에도 필수 문구·날짜·조건을 임의로 생략하지 않는다. 행사 일정은 사용자 제공 홍보 이미지의 정보이며 종료 시각은 미확정이다.

### 재생하며 확인할 것

- 지정한 한글 문구와 일정이 정확히 표시되는가?
- 문장이 차례로 이어지고 강조할 핵심어가 드러나는가?
- 마지막 행동 안내를 읽을 시간이 있는가?

참가자는 수정할 조건 하나를 적는다. 읽는 시간이 부족하다면 다음 요청을 사용한다.

```text
전체 20초는 유지하고, 마지막 일정과 댓글 안내를 4초 동안 읽을 수 있게
앞 장면의 시간을 조정해 줘. 문구와 색은 유지해 줘.
```

4초는 비교를 위한 예시 값이다. 결과가 이미 충분히 읽힌다면 같은 요청을 기계적으로 반복하지 않고 실제로 부족한 조건을 고른다. Part 1에서는 수정 문장을 남기고, 실제 전후 비교는 Part 3에서 다룬다. 수정 실행 전에는 완료 화면으로 표시하지 않는다.

**완료 기준:** 필수 문구가 정확하고, 처음부터 끝까지 재생되며, 읽는 시간에 관한 수정 조건을 설명할 수 있다. HTML 미리보기와 MP4 출력은 구분한다. 로고를 넣는 단계에서는 사용자 제공 원본을 사용한다.

## 5. 사례 B — Notion 공식 페이지로 소개 영상, 30초

**질문:** 링크 하나를 붙이면 무엇을 근거로 영상의 내용을 정해야 할까?

실습 URL은 제작자가 선정한 [Notion 공식 문서 소개](https://www.notion.com/ko/product/docs)를 유지한다. 사용자 지정 URL로 기록하지 않는다. 예시를 보고 원자료·요약·영상 문구의 관계를 설명한다.

### 시작 요청

```text
https://www.notion.com/ko/product/docs 이 페이지를 읽고,
Notion 문서를 소개하는 30초 모션 그래픽을 만들어 줘.
콘텐츠 블록·목차·공동 편집이 어떤 도움을 주는지 도형과 글자로 설명해 줘.
페이지를 읽지 못하면 먼저 알려 줘.
```

### 재생하며 확인할 것

- 이 앱이 실제 페이지를 읽었는가, 제공된 본문으로 작업했는가?
- 핵심 기능에 관한 문구가 원문에서 확인한 내용과 대응하는가?
- 기능 이름을 나열하는 데 그치지 않고 도움이 되는 상황을 설명하는가?

결과의 근거를 확인하는 다음 요청은 Part 1 안에서 사용할 수 있다. 스타일 개선과 구분한다.

```text
사용한 원문 근거와 영상 문구를 짝지어 보여 줘.
원문에 없는 주장은 제거해 줘.
```

2026-10-27의 기존 제작 기록에서는 공식 본문의 콘텐츠 유형·목차·공동 편집·댓글을 확인했다. 이 기록을 새 AI 실행의 URL 접근 성공으로 간주하지 않는다. 링크를 읽지 못하면 강사가 확인한 본문을 제공하고 입력 방식과 확인일을 기록한다.

이번 소개는 본문 내용을 자체 문장과 도형으로 재구성한다. 실제 사이트 캡처를 사용하면 개념 도식과 구분하고 이용 범위를 검토한다. 내용 근거와 시각 레퍼런스의 역할을 나누는 심화 과정은 Part 2로 넘긴다.

**완료 기준:** 원문과 영상 문구 한 쌍을 대조할 수 있고, 미확인 내용과 확인한 내용을 구분한다. 웹사이트 접근·스크린샷 자동 생성·MP4 내보내기를 확인 없이 성공으로 표시하지 않는다.

## 6. 사례 C — 원자모형 변천 지식 전달 영상, 45초

**질문:** 새로운 증거와 설명이 모형의 변화로 어떻게 이어졌을까?

톰슨·러더퍼드·보어를 선택한 기존 방향을 유지한다. 단순 인물 타임라인보다 각 모형의 차이와 바뀐 이유를 이해하는 데 목적을 둔다.

### 시작 요청

```text
톰슨·러더퍼드·보어의 원자모형이 어떻게 달라졌는지 설명하는
45초 모션 그래픽 초안을 만들어 줘.
각 모형의 차이와 모형이 바뀐 이유를 짧은 문장과 모식도로 보여 줘.
새로 확인해야 할 사실은 따로 표시해 줘.
```

### 재생하며 확인할 것

- 각 모형에서 달라진 설명이 드러나는가?
- 관찰 결과와 그것을 해석한 모형의 설명이 구분되는가?
- 인물·연도·주요 주장에 대응하는 근거가 있는가?

첫 결과는 설명 초안이다. 이 파트에서는 근거가 필요한 주장 하나를 표시하고 기존 자료와 대조한다. 후속 요청은 다음처럼 작성하되, 전체 장면표 작성은 Part 4에서 한다.

```text
각 모형에서 바뀐 설명을 먼저 문장으로 정리하고,
그 문장과 도형의 움직임을 연결해 줘. 근거가 없는 연출은 빼 줘.
```

기존 전개의 검토 항목은 질문 → 톰슨 모형의 특징 → 산란 관찰과 러더퍼드의 해석 → 보어 모형의 변화 → 모형이 바뀌는 이유의 정리다. 기존에 확인한 자료는 [AIP 원자핵 발견사](https://history.aip.org/exhibits/rutherford/sections/alpha-particles-atom.html)와 [Manitoba Education Appendix 2.3, A27~A29](https://www.edu.gov.mb.ca/ks4/cur/science/found/s1/appen2.pdf)다. 새 생성 결과에 사실이 추가되면 해당 주장도 원문에서 확인한다. 출처가 적혀 있다는 이유로 확인 완료로 처리하지 않는다.

**완료 기준:** 설명의 차이와 미확인 주장을 지목할 수 있다. 최종 제작 전에는 인물·연도·모형 설명을 근거와 대조한다. 모식도를 실제 크기 비율·관측 궤적으로 오해하게 하거나 보어 모형을 현대 원자모형의 최종 형태로 설명하지 않는다. 현재 사례에 내레이션·실험 재현 영상을 자동 추가하지 않는다.

## 7. 참가자 기록과 오류 시 합류

| 사례 | 시작 입력 | 내 결과 또는 관찰 | 고칠 조건 한 문장 | 저장 위치 |
|---|---|---|---|---|
| A / B / C 중 선택 | 문장 / URL / 주제·자료 | 재생 확인·근거·미확인 내용 | 대상과 시간·강조·순서·내용 조건 | 실제 파일 또는 작업 링크 |

| 상황 | 확인과 대응 | 계속할 활동 |
|---|---|---|
| 정지 이미지만 나옴 | 시간에 따라 변하는 움직임과 재생 결과를 요청 | 첫 결과와 필요한 동작의 차이 기록 |
| 생성 대기·도구 오류 | 같은 요청의 상태 확인, 중복 요청 대신 사전 결과 사용 | 사전 실행임을 표시하고 동일 기준으로 관찰 |
| URL 접근 불가 | 확인된 본문을 제공하고 직접 열람과 구분 | 원문·요약·문구 한 쌍 대조 |
| 역사 설명의 근거 미확인 | 원문 자료와 대조, 미확인 부분 표시·검증 또는 제외 | 배포 전 확인할 주장 기록 |
| HTML은 재생되지만 MP4가 없음 | 미리보기와 파일 출력의 확인 상태를 구분 | 재생 관찰과 저장 위치 기록 |

선택한 도구의 유료 계정 준비 조건은 유지한다. 기술 오류나 생성 지연은 관찰·백업 결과로 합류할 수 있다. 생성 속도·모델 성능 순위·외부 도구 가격을 실습 성공 조건으로 제시하지 않는다.

## 8. 장표·실제 캡처·제작 상태

기초에서는 **뜻 → 표현 유형 → 기본 변화 → 효과 이름 → 시간과 속도 → 요청 문장** 순서로 설명한다. 그다음 각 사례를 **예시 → 시작 요청 → 실제 결과 → 관찰·수정 조건**으로 진행한다. 실제 앱 캡처는 이 관계를 뒷받침하는 보조 자료로 사용한다. 기존 대표본의 예시 화면·흰 프롬프트 박스·비교 유형과 내용 슬롯을 적용하고, UI 캡처 개선을 전체 재설계로 확대하지 않는다.

Codex·Claude의 입력·생성·재생·수정 화면을 사용할 때는 각 앱에서 확보한 실제 화면과 원본 캡처·확인일·작업 연결을 남긴다. 대화와 결과의 관계를 유지하며 입력창 조각만 확대하지 않는다. 원본 레퍼런스의 R05 31쪽·R03 31쪽은 기능적 배치 참고 이력이며, 기존 대표본을 바꾸거나 추출 픽셀·원문 사례를 재사용하는 지시가 아니다. 관련 [디자인 기준](design.md)과 [G10](../../docs/copyright-review.md)을 따른다.

| 자료 | 현재 상태와 사용 범위 |
|---|---|
| 기존 대표 5장·현재 9장 | 디자인 기준으로 보존. 이번 문서 개정에서 변경 없음 |
| 이전 A의 실제 Claude 실행 | [대화](https://claude.ai/chat/13929648-6e5f-432b-abdc-0ff7440bb057)와 `assets/three-cases-v2/claude/captures.json`에 기록. 20초 HTML 자동 재생·처음부터 재생·3초 이동과 원본 캡처 5개 확보. 이번 개정 프롬프트의 새 실행·수정·MP4 출력 증거는 아님 |
| B·C 및 새 Codex 실행 | 새 사례의 요청·재생·수정 캡처 미제작 |
| `output/webinar-three-cases-v2/`의 MP4 3종 | 별도 코드로 만든 무음 예제 20·30·45초, 1280×720·24fps. 앱 출력 증거나 후속 디자인 승인 기준으로 사용하지 않음 |
| 거부된 UI PPT·이전 질문 영상 | 이력 보존. 최신 장표의 디자인·실행 완료 근거로 재사용하지 않음 |
| 이번 분석 반영 | 강의 계획과 설명·요청·완료 기준 개정. 새 영상·UI 캡처·외부 생성·G10 승인 없음 |
