# Part 1 — 세 가지 출발점으로 모션 그래픽 만들기

2026-10-27 · 사용자가 ‘이 조합으로 수정’이라고 선택한 예제 방향 반영. 예제 방향 선택은 디자인·권리·전체 계획의 승인을 의미하지 않는다.

먼저 Part 0에서 **코덱스 or 클로드 유료 요금제**와 로그인·작업 폴더를 확인한다. Part 1은 앱의 버튼 설명보다 완성 영상과 입력 자료의 관계를 먼저 보여 준다.

## 최신 정정 — 기존 대표 5장을 디자인 기준으로 유지

사용자는 기존 대표 5장이 좋았다고 했고 직전의 임의 재구성을 거부했다. 작업 기준은 `output/webinar-samples/NotionTalk_모션그래픽_주황포인트_자체사례_v5.pptx`다. 주황 그라데이션 표지·세 캐릭터·상단 안내·중앙 제목·카드·문서 표·흰 프롬프트 박스·로고·푸터·서체·간격을 보존한다. 기존 파일을 덮어쓰거나 새 다섯 장으로 교체하지 않는다.

사용자가 선택한 세 예제와 Part 0 등 최신 내용은 유지한다. 새 예제·실제 앱 캡처는 기존 대표본의 해당 유형을 확장하고 내용 슬롯만 바꾼다. 캡처 개선 요청을 대표본 전체 재설계 허가로 해석하지 않는다. 직전 `webinar-three-cases-v2`의 새 5장은 비채택 검토 이력이며 후속 디자인 기준이 아니다.

기준 파일 식별·해시는 단원 `checks/design-baseline.json`에 기록했다. 사용자의 기존 대표본에 대한 긍정 평가와 정확한 파일명을 명시한 정식 게이트 승인을 구분한다. 기존 G10 검토 상태를 변경하지 않는다.

## 도입: 만들 수 있는 영상의 종류

타이포그래피·인포그래픽·서비스 소개·역사 타임라인·절차 안내·캐릭터 설명을 짧은 결과로 소개한다. 이어서 이번 웨비나의 세 가지 제작 사례를 보여 준다. 타이포그래피는 표현 형식, URL은 원자료 입력 방식, 과학사는 설명 주제다.

| 사례 | 이번 예제 | 시작 입력 | 영상에서 볼 것 |
|---|---|---|---|
| A. 텍스트 | 노션톡 무료 웨비나 홍보 타이포그래피 | 홍보 문장과 행사 정보 | 문장이 이어지는 리듬·핵심어의 크기와 위치 변화 |
| B. 웹사이트 | Notion 공식 문서 페이지 소개 | https://www.notion.com/ko/product/docs | 콘텐츠 블록·목차·공동 편집을 새 장면으로 재구성 |
| C. 과학사 | 톰슨·러더퍼드·보어의 원자모형 변천 | 설명 주제와 확인할 자료 | 모형의 차이와 바뀐 이유를 글·모식도로 설명 |

세 주제의 조합은 사용자 선택이다. B의 구체 URL은 제작자가 고른 실습 예시이며 사용자 지정 URL로 기록하지 않는다. 길이 20·30·45초는 제작 예시의 길이다.

## A. 노션톡 웨비나 홍보 타이포그래피

단순한 문장 요청으로 시작한다. 대표 장표에는 짧은 시작 요청을, 실제 앱 시연에는 행사 정보를 더한 아래 요청을 그대로 남긴다.

> ‘수업 자료가 영상이 되는 순간’으로 시작하는 노션톡 무료 웨비나 홍보 타이포그래피 영상을 20초로 만들어 줘. 글자가 차례로 이어지면서 핵심어의 크기와 위치가 바뀌게 해 줘. 검정 바탕에 주황색 포인트를 쓰고, 마지막에는 ‘2026년 11월 1일 일요일 저녁 8시’와 ‘댓글에 노션톡을 남겨 주세요’를 넣어 줘. 바로 재생할 수 있는 아티팩트로 보여 줘.

관찰: 글자 자체의 움직임·강조·읽는 시간·마지막 행동 안내. 첫 수정은 ‘마지막 일정 화면이 2초 더 머물게 해 줘’처럼 한 조건만 바꾼다. 실제 수정 실행 전에는 수정 완료 화면으로 표시하지 않는다.

## B. 웹페이지 내용으로 소개 영상

> https://www.notion.com/ko/product/docs 이 페이지를 읽고 Notion 문서를 소개하는 30초 영상을 만들어 줘. 콘텐츠 블록·목차·공동 편집을 도형과 글자로 설명해 줘. 페이지를 읽지 못하면 먼저 알려 줘.

2026-10-27 실제 공식 본문에서 코드·이미지와 동영상 등 콘텐츠 유형, 목차, 공동 편집·댓글을 확인했다. 영상은 원문 UI 스크롤 녹화가 아니라 이 내용을 자체 문장과 도형으로 재구성한다. 실습 AI가 읽었다는 주장은 앱별 실제 실행 때 따로 확인한다. 제작자의 웹 열람을 AI의 URL 읽기 성공으로 바꾸지 않는다.

원자료: [Notion 공식 문서 소개](https://www.notion.com/ko/product/docs). 원문 이미지·로고·문구는 예제 영상에 복사하지 않았다. 내용을 확인한 근거와 소재 재사용 권리는 G10에서 구분한다.

## C. 원자모형 변천을 설명하는 영상

> 톰슨·러더퍼드·보어의 원자모형이 어떻게 달라졌는지 45초 영상으로 설명해 줘. 모형을 도형으로 보여 주고, 연도와 설명의 출처도 적어 줘.

전개: ‘보이지 않는 원자, 모형은 왜 바뀌었을까?’라는 질문, 퍼진 양전하 속 전자의 톰슨 모형, 산란 결과와 집중된 중심을 연결한 러더퍼드의 1911년 설명, 정해진 에너지 상태를 도입한 1913년 보어 모형, 새로운 증거와 설명에 따라 모형이 바뀐다는 정리.

근거: [AIP 원자핵 발견사](https://history.aip.org/exhibits/rutherford/sections/alpha-particles-atom.html), [Manitoba Education Senior 1 Science Appendix 2.3, A27~A29](https://www.edu.gov.mb.ca/ks4/cur/science/found/s1/appen2.pdf). 전자는 모식도상 표시이며 실제 크기 비율·관측 궤적이 아니다. 보어 모형을 현대 원자모형의 최종 형태라고 설명하지 않는다. 나레이션·실험 재현 영상은 현재 예제에 포함하지 않았다.

## 장표와 캡처 구성

기본 순서: 완성 예시 → 시작 요청 → 실제 제작 화면 → 결과 재생 → 한 조건 수정. 상단 Part·번호·소주제, 중앙 제목과 짧은 부제, 아래 예시 화면과 프롬프트를 따른다. 원본 R05 31쪽의 요청 장표와 R03 31쪽의 요청·결과 비교 구조를 실측하여 사용한다. 원본의 사례·문구·배경 픽셀은 복사하지 않는다.

요청 장표는 좌측 예시·우측 흰 프롬프트 박스, 실제 실행 장표는 요청·결과가 연결되어 보이는 앱 캡처를 사용한다. 맥락 없이 입력창 한 조각만 크게 자르고 옆에 일반 설명을 붙이는 이전 방식은 제외한다. 원본 캡처는 별도 보존하고, 강의 화면에서 필요한 범위를 사용하더라도 대화·입력·결과의 관계를 유지한다.

## 제작 상태와 자료 구분

`output/webinar-three-cases-v2/`의 세 MP4는 이 작업에서 직접 코드로 제작한 무음 모션 예제다. 각 20·30·45초, 1280×720, 24fps이며 전체 프레임 디코딩 검사를 통과했다. 새 사례의 영상 방향을 확인하는 자료이며 Codex/Claude에 요청한 결과라고 표시하지 않는다. PPT에는 영상의 정지 프레임을 넣고 MP4는 별도로 동봉한다.

실제 Claude 실행 기록은 `assets/three-cases-v2/claude/captures.json`과 연결한다. 대화: https://claude.ai/chat/13929648-6e5f-432b-abdc-0ff7440bb057 . A의 실제 입력·생성·20초 HTML 아티팩트 자동 재생·처음부터 재생·3초 지점 이동을 확인했고 원본 캡처 5개를 보존했다. 대표 PPT 4~5장은 실제 요청과 생성 결과, 3초 지점의 큰 결과 화면이다. 입력 전 화면은 원본 기록으로 보존한다. HTML의 MP4 내보내기는 확인하지 않았다. B·C의 실제 인앱 요청·재생·수정 캡처 및 새 Codex 실행은 아직 미제작이다.

이전 질문 영상과 캡처 15개·두 앱 조작 PPT 12장은 이력으로 보존한다. 사용자가 디자인과 예제 모두를 거부했으므로 새 대표 시안의 승인 근거로 사용하지 않는다. 새 대표 시안도 사용자 디자인 확인 전이다. G10 검토 완료를 표시하지 않는다.
