# 이번 웨비나의 장표·캡처 디자인 기준

2026-10-27 · 최신 사용자 거부 피드백 반영. 대표 시안의 사용자 디자인 확인은 미완료.

## 요청 장표

직접 확인한 R05 31쪽의 기능적 구성을 따른다. 1920×1080에서 Part (90,89), 번호 (90,131), 소주제 (162,131), 중앙 제목 y299, 부제 y404, 좌측 예제 (395,573,426,240), 우측 요청 박스 (940,562,585,314)다. 원본 예시는 426×290이므로 새 16:9 영상은 가로폭을 유지하고 높이를 240으로 맞췄다. 새 제목은 1360px 폭 안에 중앙 정렬했다. 원문의 버튼·피그마 예시·문구는 쓰지 않는다.

배경 #000000, 본문 흰색, 강조 #FF9228. 요청 박스는 흰색 바탕·검정 본문·회색 요청 유형. native roundRect·텍스트 상자로 재구성하며 PDF 배경 픽셀은 복사하지 않는다. 원본 익명 Type3 글꼴을 특정하지 못했으므로 실제 설치된 Pretendard를 사용한다. 동일 폰트라고 주장하지 않는다.

## 실제 실행 장표

R03 31쪽의 ‘중앙 제목 + 좌측 요청 + 우측 결과’ 구성을 참조한다. 실제 프롬프트는 네이티브 텍스트로 읽을 수 있게 두고 앱 원본 캡처에는 입력·응답·미리보기의 맥락을 보존한다. 입력창 조각을 크게 붙이고 옆에 일반적인 조작 설명을 길게 쓰던 이전 12장 방식은 사용자 거부 상태다.

원본 캡처는 해시·날짜·앱·대화 URL·정확한 요청을 보존한다. 실제 입력 화면·생성 상태·재생 화면을 확보한 범위만 표시한다. 장표에 넣기 위해 가짜 UI를 만들거나 로컬 코드 영상의 프레임을 실제 인앱 결과로 바꾸지 않는다. 예제 영상 3종과 Claude에서 생성한 아티팩트는 출처·파일 형식을 분리한다.
