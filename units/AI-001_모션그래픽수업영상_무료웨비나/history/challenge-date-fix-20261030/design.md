| 원본 보존, 출처 기록, 실제 렌더 검토 | 강조색 한 가지, 표지 장면 |

기존 과학 수업의 네 캐릭터·교복·실험복·엔탈피 그림·단원별 색상·T셀파 로고는 해당 과학 수업에만 적용한다. 새 강의의 브랜드는 사이음/노션톡 중 사용자가 처음 지정한 것을 사용한다. 지정이 없으면 반드시 **“이번에는 사이음/노션톡 중 무엇인가요?”**라고 질문한다. 이전 강의의 선택을 새 강의에 자동 적용하지 않는다.

모든 장표 우측 상단에는 선택한 원본 로고를 넣는다. 사이음은 원본 하네스 자산, 노션톡은 [등록한 자산](assets/branding/README.md)의 흰색/검정색 원본을 사용한다. 어두운 배경에는 흰색, 밝은 배경에는 검정색을 선택한다. 원본 형태·질감·비율·투명도를 유지하며 원본 미확보를 임의 생성이나 텍스트로 대체하지 않는다.

푸터의 권리자는 사이음이면 `Sci_eum`, 노션톡이면 `NotionTalk`이다. 기존 문구에서 해당 부분만 바꾸고 연도·기호·접두·접미 문장은 유지한다. 기본 예시 `© 2026. Sci_eum. All rights reserved.`는 노션톡이면 `© 2026. NotionTalk. All rights reserved.`가 된다.

라이브는 어두운 테마를 기본으로 제안한다. 인쇄가 필요한 자료는 별도 밝은 테마로 만든다. 한 강의 본문에서 배경색을 장마다 번갈아 바꾸지 않는다. 사용자가 별도 참고 디자인을 지정하면 강의 계획에 적용 범위와 바뀌는 기준을 기록한다.

## 3. 색상

강조색을 바꿀 때는 강의 전체에서 한 계열로 바꾼다. 원본들에서 보이는 분홍·보라·청록을 동시에 섞어 쓰지 않는다. 밝은 강조색으로 채운 영역에는 어두운 글자를 쓴다. 원본 UI·사진·차트의 의미 있는 색은 보존한다. 성공·실패는 색과 함께 문구 또는 기호로 구분한다.

## 4. 글꼴·크기·문장

한글 기본 글꼴은 Pretendard를 제안한다. 실제 렌더러에 글꼴 파일이 로드되는지 확인하고, 사용 환경에서 지원하는 대체 글꼴도 점검한다. 명령어·코드는 Cascadia Mono 또는 Consolas처럼 영문·기호를 구분하기 쉬운 고정폭 글꼴을 사용한다. 한글이 섞인 프롬프트에는 읽기 쉬운 한글 글꼴을 쓸 수 있다.

좌표 기준은 1920×1080px다. 아래 PPT 값은 **13⅓×7.5인치, 960×540pt** 슬라이드로 제작할 때의 환산 시작값으로 `1pt ≈ 2px`다. 원본 PDF의 1920×1080 페이지 단위를 PPT 포인트로 그대로 옮기지 않는다.

| 요소 | 렌더 기준 px | PPT 기준 pt | 굵기 |
|---|---:|---:|---|
| 표지 제목 | 96~112 | 48~56 | Bold |
| Part 전환 제목 | 88~104 | 44~52 | Bold |
| 본문 핵심 제목 | 64~80 | 32~40 | Bold |
| 소주제·핵심 설명 | 40~48 | 20~24 | SemiBold/Medium |
| 본문·실습 지시 | 36~44 | 18~22 | Medium/Regular |
| 명령·프롬프트 | 34~40 | 17~20 | Regular/Medium |
| Part 위치 안내 | 28~32 | 14~16 | Medium |
| 출처·짧은 주석 | 24~28 | 12~14 | Regular |

- 제목은 보통 1~2줄, 주요 설명은 짧은 문장으로 쓴다. 글자를 계속 줄여 끼우지 말고 화면 확대·장표 분할·배포 파일을 활용한다.
- 짧은 제목은 ‘파일 업로드’, ‘결과 확인’, ‘로그인 오류’처럼 주제를 바로 적는다. 문제를 여는 질문형 제목은 필요한 도입에 사용한다.
- `설명`, `강사 시연`, `함께 실습`, `직접 실습`, `결과 확인`, `오류 대응`은 실제로 행동이 바뀌는 장에서 표시한다. 청중이 클릭해야 하는 화면에 강사 시연만 하는지 구분해 준다.
- 낯선 용어는 처음 한 번 한국어 뜻과 함께 소개한다. 버튼·메뉴·파일명은 실제 UI의 표기와 일치시킨다.
- 강조는 바꿀 입력·현재 단계·판단 기준에 집중한다. 문장 전체를 강조색으로 칠하지 않는다.
- 제목·보조 문장·아래 요약에서 같은 말을 반복하지 않는다. 강사의 제작 메모와 검수 코멘트는 수강생 화면에 넣지 않는다.

## 5. 공통 배치와 여백

다음 좌표는 새로운 제작의 출발점이다. 참조 잠금 좌표나 자동 게이트의 허용 오차를 정한 것이 아니다.

| 영역 | 1920×1080 기준 제안 | 내용 |
|---|---|---|
| 안전 영역 | 좌우 80px, 위아래 48px 이상 | 중요한 글자·표·캡처 라벨 보호 |
| 위치 안내 | x80, y48 부근 | Part명과 소주제. 작은 안내와 큰 제목 분리 |
| 소주제 | y96~160 | 강조색 번호와 구체적인 주제 |
| 핵심 제목·설명 | y210~350 | 중앙 또는 자료 방향에 맞춘 왼쪽 정렬 |
| 주요 자료 | y390~940 | 화면·입력·결과·표·비교 그림 |
| 출처·진행 정보 | y1000 부근 | 짧은 출처, 페이지 번호, 강의 식별 정보 |

16px 간격의 배수를 시작점으로 사용하고 캡처 크기에 맞춰 조정한다. 표지와 Part 전환은 별도 구도를 사용한다. 큰 작업 화면이 필요한 페이지는 중앙 제목의 높이를 줄이고 제목과 캡처를 우선 배치한다.

상단 Part는 `Part 1`로 통일한다. 같은 개념의 설명·실습·확인은 같은 소주제 번호를 사용하며 페이지마다 번호를 늘리지 않는다. 실제 페이지 번호는 재참조를 위해 작은 고정 위치에 표시한다. 과학 수업의 ‘페이지 번호 제거’ 지침을 새 연수에 가져오지 않는다.

로고는 제공된 원본의 색·비율을 보존하고 모든 장표 우측 상단에 배치한다. 배치할 원본이 없으면 실제 제작 전에 위치를 확인한다. 우측 상단 로고 영역이 있는 원본을 참조할 때는 선택한 사이음/노션톡으로의 대응을 참조 기록에 남긴다. 자동 검사는 실제 표시 경계가 우측 상단에 있는지와 등록 자산 해시, 하단 `copyright_footer`의 실제 문구를 확인한다.

## 6. 슬라이드 유형과 기존 7유형 연결

아래 유형은 대표 시안과 전체 제작에서 재사용한다. 목록의 개수만큼 모든 강의에 장을 억지로 추가하지 않는다. 자동 검사는 7유형을 유지하면서 과학 전용 필수 역할을 연수용 제목·입력·결과와 선택한 브랜드로 전환했다.

| 기존 유형 | 연수용 구성 | 실제 참조 |
|---|---|---|
| `cover` 표지 | 왼쪽 큰 강의명·짧은 부제·강사/일시, 오른쪽 주제 장면 또는 실제 결과 | R01 1쪽, R04 1쪽, R07 1쪽 |
| `part` 전환 | 강조색 Part, 흰 큰 제목, 다음에 할 행동을 설명하는 짧은 문장 | R04 6쪽, R02 103쪽, R07 25쪽 |
| `objectives` 수행 목표 | 강의 후 할 수 있는 행동과 남길 결과물. 완료 기준이 보이는 간결한 구성 | R01 3쪽, R02 8쪽의 결과·진행 구성에서 조정 |
| `contents` 목차 | 꺾인 블록 또는 단순한 흐름으로 현재 강의의 구간 표현 | R01 2쪽, R03 2쪽, R06 2쪽 |
| `figure` 화면·도식 | 큰 실제 캡처, 필요한 확대와 번호 주석, 한 줄 관찰 안내 | R03 31·37쪽, R04 15·39쪽 |
| `table_formula` 명령·프롬프트·표 | 복사할 입력과 설명, 또는 명령/역할 표. 수식이 없으면 억지로 넣지 않음 | R04 10·11쪽, R01 10쪽, R05 31쪽 |
| `comparison` 비교·오류 대응 | 같은 기준의 입력/결과, 수정 전/후, 증상/조치 | R01 87쪽, R04 25·46쪽, R06 67쪽 |

`objectives`의 새 구성, 추가 상태 표기, 아래 실습 레이아웃은 제작 제안이다. 원본에서 그 유형이 정확히 같은 모양으로 존재한다고 주장하지 않는다. 대표 시안에는 채택 근거와 조정한 요소를 함께 기록한다.

### 화면 안내

한 장의 큰 캡처를 우선한다. 전체 화면으로 위치를 알려준 뒤 다음 장 또는 같은 장의 확대 영역에서 입력 위치를 보여준다. 캡처를 작게 줄여 여러 창을 얹기보다 단계별로 나눈다. 번호 주석과 짧은 설명은 일대일로 연결하고 같은 페이지에서 설명하는 조작만 강조한다.

### 입력과 결과

입력은 왼쪽, 예상 결과는 오른쪽을 기본으로 하되 화면 비율에 따라 위아래로 바꿀 수 있다. 실행 위치·복사할 내용·성공 조건을 구분한다. 실제 클릭 가능한 제품 버튼과 설명용 도형이 혼동되지 않게 한다. ‘복사’라는 가짜 버튼 대신 실제 배포 텍스트 링크를 제공한다.

### 직접 실습

수행 과제, 사용할 자료, 예상 시간, 완료 확인을 짧게 보여준다. 강사가 설명을 멈추고 기다리는 지점은 강사용 대본에 적는다. 모든 실습에 초 단위 카운트다운을 넣지 않는다. 끝낸 사람의 추가 과제와 늦어진 사람의 합류 경로는 필요할 때 별도 장으로 둔다.

### 오류 대응

‘증상 / 먼저 확인할 것 / 조치 / 정상 결과’를 기준으로 구성한다. 긴 오류 전문은 텍스트 배포본에 두고 핵심 오류 문자열과 화면 위치를 보인다. 명령어가 실행되는 제품·쉘·경로를 섞지 않는다. 정확한 실행·복구 절차는 제작 시 실제 환경에서 확인한다.

### 결과 비교

같은 입력 조건과 비교 기준을 적는다. 생성형 AI의 예시 결과는 ‘예시’로 표시하고 문장 전체가 같아야 성공하는 것처럼 만들지 않는다. 수정 전후는 바뀐 부분과 수정 이유를 연결한다. 양쪽 화면의 크기·배율을 맞추거나 차이를 표시한다.

## 7. 캡처·명령어·프롬프트 처리

- 사용법은 실제 제품 화면을 캡처한다. 캡처별 제품·버전 또는 확인 환경, OS, UI 언어, 날짜, 원본 경로를 자산 기록에 남긴다.
- 입력창만 확대하더라도 화면의 위치를 알아볼 수 있는 메뉴·창 제목 등 맥락을 남긴다. 성공 표시·오류 문구·필수 결과를 잘라내지 않는다.
- 원본 비율을 유지한다. 큰 캡처 안의 작은 글자는 전체 이미지를 늘리는 것으로 해결하지 말고 관련 부분을 다시 캡처하거나 확대한다.
- 실제 계정 화면에 포함된 이름·이메일·API 키 등은 예시 계정으로 대체하거나 필요한 부분만 가린다. 가림 처리가 조작 위치나 성공 표시를 덮지 않게 한다.
- 명령·프롬프트·파일명은 편집 가능한 텍스트로 작성하고 원문 파일도 제공한다. 캡처에 박힌 코드를 복사 가능한 입력이라고 설명하지 않는다.
- 코드의 따옴표·하이픈·들여쓰기를 보존하고 복사 실행을 확인한다. 쉘 프롬프트 기호를 실행할 명령에 섞지 않는다. 긴 한 줄 명령을 화면에서 나눌 때는 배포 원문의 실행 가능성을 보존한다.
- 바꿀 자리는 `<내 폴더 경로>`처럼 표시하고 무엇으로 바꿀지 설명한다. Windows와 macOS의 명령·경로가 다르면 분리해 표시한다.
- 교재 PDF의 코드 추출문은 자간·줄바꿈이 깨질 수 있다. 원본 화면과 공식 문서로 대조하기 전에는 실행 가능한 명령으로 배포하지 않는다.

## 8. 표·도식·이미지·모션

표는 비교할 정보가 있을 때 사용한다. 제목·문장 열은 왼쪽, 짧은 상태·숫자는 비교하기 쉬운 정렬을 택한다. 원본이 짙은 바탕의 표라면 글자 대비와 행 간격을 유지한다. 셀마다 두꺼운 테두리를 반복하지 않는다.

도식에는 실제 관계·입력·출력·순서를 담는다. 수강생이 알아야 할 정보에만 도형을 쓰고 장식용 카드 격자를 페이지마다 반복하지 않는다. 도식의 설명과 화살표 방향을 일치시킨다.

표지·비유·전환에 필요한 삽화만 사용한다. 캐릭터를 쓸 경우 기준 이미지를 등록하고 고정 외형과 장면별 동작·소품을 구분한다. 입력창·긴 코드·큰 결과 화면에는 장식용 캐릭터를 넣지 않는다. R06의 외형 고정 방식을 참고하되 원본 캐릭터 자체를 새 자산으로 가져오지 않는다.

화면 캡처·로고·기존 삽화는 원본 자산을 우선한다. 생성 이미지에는 정확한 메뉴·오류·성공 표시를 그리게 하지 않는다. 생성 이미지를 실제 사용한 경우 사용 사실과 원본 출처를 노트·자산 기록에 남긴다. 필요한 공개 고지는 강의 계획의 배포 조건을 따른다.

모션은 클릭 위치·단계 공개·결과 변화의 이해에 필요한 경우만 사용한다. R02의 PDF는 실제 속도·이징의 검증 근거가 아니다. 재생 가능한 원본을 확보한 경우에만 동작을 분석한다. PDF 배포본에서는 공개 순서가 없어도 이해되도록 최종 상태나 연속 캡처를 제공하고, 영상 링크가 있으면 열리는지 확인한다.

## 9. 출처·브랜드·배포본

출처의 상세 정보는 발표자 노트와 대본에 기록한다. 형식은 `출처: 파일명, PDF 쪽/PPTX 장 또는 공식 URL, 확인일, 적용 조건`을 기본으로 한다. 수강생이 열어야 하는 사이트·실습 자료는 본문에서 짧은 링크 또는 QR과 함께 안내한다. QR만 두고 클릭 가능한 링크를 빼지 않는다.

원본 로고·저작권 문구·강사명·행사 날짜를 그대로 복사하지 않는다. 사용자가 제공한 새 강의의 브랜드만 반영한다. 저작권 연도와 권리자는 실제 정보로 적는다. 미확정 기관 로고 위치를 확인된 원본 규칙이라고 쓰지 않는다.

PPTX에서는 제목·설명·명령·표를 가능한 한 편집 가능하게 유지한다. PDF는 같은 내용·순서의 배포본으로 만들고, 밝은 테마 변환 시에는 이미지·코드·주석의 대비를 다시 확인한다. 강사용 DOCX는 슬라이드별 발화와 시연 조작·대기·오류 대응을 구분한다. Figma를 검토 경로로 선택하면 관련 스킬을 읽고 원격 화면과 대응을 실제로 확인한다.

## 10. 참조 기록과 대표 디자인 확인

대표 시안은 기존 7유형을 유지하되 아래 기록으로 새 강의에 맞게 연결한다.

| 기록 | 내용 |
|---|---|
| 참조 | 실제 파일·해시·쪽/장·렌더 이미지 |
| 채택 | 제목 위계, 주요 자료 비율, 여백, 강조·표현 방식 |
| 교체 | 강의 내용, 실제 도구 화면, 강사·기관 브랜드 |
| 조정 | 목표 유형 재구성, 캡처 확대, 접근성·인쇄용 변경과 이유 |
| 비교 | 현재 시안의 렌더, 원본/시안 대조, 항목별 검토 |
| 확인 | 그 버전에 대한 실제 사용자 피드백과 반영 상태 |

전체 재현인지 일부 구성 차용인지 먼저 명시한다. 이번 요청은 여러 레퍼런스를 분석해 새 용도의 기준을 만드는 작업이므로 **요소별 채택**으로 기록한다. 이후 정확한 원본 재현을 요청받으면 파일·쪽·좌표를 고정한 별도 계약을 따른다. 통과를 위해 참조를 다른 페이지로 바꾸거나 허용 오차를 넓히지 않는다.

기본 연수 프로필은 G08에서 `exact` 또는 `adopt`를 명시하게 한다. 요소 차용은 원본과 목표 템플릿의 변경을 모두 선언하고 시안은 고정한 목표와 비교한다. 캐릭터·T셀파를 일괄 요구하지 않으며 로고는 강의별 납품 계약을 따른다. G09는 현재 참조·시안 버전에 대한 실제 사용자 확인을 검사한다. 상세 파일 형식은 [연수용 데이터 계약](docs/ai-training-contract.md)을 따른다.

## 11. 시각·사용성 검수

- [ ] 현재 Part와 활동 유형이 분명하고, 제목·보조 문장·자료가 같은 목적을 전달하는가?
- [ ] 한 페이지에 설명할 핵심이 하나이며, 긴 내용을 작은 글자로 축소하지 않았는가?
- [ ] 실제 캡처의 메뉴·입력창·성공 표시·오류 문구가 읽히고 필요한 맥락이 남아 있는가?
- [ ] 입력 위치, 복사할 내용, 바꿀 값, 예상 결과, 성공 확인 방법이 연결되는가?
- [ ] 명령·프롬프트 원문을 복사할 수 있고 실제 환경에서 실행·확인했는가?
- [ ] 현재 버전·OS·언어·계정 조건과 캡처가 일치하는가?
- [ ] 결과가 달라도 성공 기준으로 판단할 수 있고, 늦어진 수강생이 합류할 경로가 있는가?
- [ ] 표·캡처·강조 표시가 겹치거나 잘리지 않고, 색만으로 성공·실패를 구분하지 않는가?
- [ ] 잘못 복사한 로고·캐릭터·날짜·저작권 문구가 없는가?
- [ ] 화면 전체를 이미지로 넣은 페이지의 편집 가능성을 과장하지 않았는가?
- [ ] PPTX·PDF·대본의 페이지·내용·링크가 대응하고 PDF만 읽어도 절차를 이해할 수 있는가?
- [ ] 실제 렌더와 실습 리허설을 확인하고, 자동 검사 결과와 사람의 시각 판단을 구분했는가?

사용자의 대표 디자인 확인과 기술 검증은 별개다. 업로드 성공, 이미지 생성 성공, 문서 체크리스트의 존재만으로 전체 디자인 확인이나 실습 재현 완료를 선언하지 않는다.
