# Part 1 — 짧은 요청으로 수업 시작 영상 만들기

2026-10-27 · 구성 제안. 전체 90분·42장 초안 중 5~10장, 12분. 전체 순서는 단순 프롬프트 → 레퍼런스 → 모션 지식 → Markdown 문서 → 외부 커넥터를 유지한다.

## 최신 반영: 코덱스·클로드 실제 시연

사용자 요청에 따라 두 데스크톱 인앱에서 같은 첫 프롬프트와 시간 수정 프롬프트를 실제 실행하고 원본 캡처 15개를 확보했다. 조작별 보조 자료는 코덱스 6장·클로드 6장이다. [캡처·요청·환경 기록](assets/ui-captures/20261027/README.md)과 [보조 PPTX](../../output/webinar-ui-guide/NotionTalk_Part1_실제앱_단계별캡처_v1.pptx)를 따른다.

| 환경 | 실제 첫 결과 | 실제 시간 수정 결과 | 확인 범위 |
|---|---|---|---|
| Codex 인앱, GPT-6.1 Sol Medium | 10초 MP4 | 11초 MP4 | 실제 재생, 질문 장면 탐색, 가운데 질문 개인화와 11초 유지 |
| Claude Desktop 3.6556.2.0, Opus 5.5 높음 | 10초 HTML 아티팩트 | 11초 HTML 아티팩트 | 실제 재생·버튼·시간 수정. 내보내기는 메뉴 위치까지 확인 |

위 표는 이번 계정·환경에서 관찰한 결과이며 제품의 고정 동작이나 무료 범위를 뜻하지 않는다. 클로드 HTML을 MP4로 표시하지 않는다. 코덱스 첫 요청과 시간 수정은 사용자가 허용한 실습용 별도 채팅 도구로 전달했고, 개인화 요청은 실제 인앱 입력창에 입력·제출했다. 클로드는 실제 새 대화의 입력창에서 입력·제출했다. 화면 속 전달 경로 표시를 지우거나 가짜 입력 화면으로 재구성하지 않았다.

아래 여섯 장은 학습 흐름을 정한 초안이다. 실제 PPT에는 필요한 조작별 보조 장표를 끼워 넣는다. 12분 운영은 한 환경을 중심으로 실습하고 다른 환경은 실제 캡처로 비교하는 안이다. 두 환경의 전체 과정을 연속 실습할 경우 시간·전체 장수는 리허설 후 다시 합산한다. 기존 42장과 90분을 확정값으로 두고 새 화면을 압축하지 않는다.

## 학습 경험

참가자는 수업을 시작할 때 보여 줄 짧은 글자 영상을 만들고 실제로 재생한다. 학생이 질문을 읽을 수 있는지 확인한 뒤 조건 하나를 바꾸고 전후 차이를 설명한다. 성공 기준은 지정 문구 3개의 정확성, 등장 순서, 수정 조건의 확인이다. 직접 실행이 어려운 참가자는 강사의 실제 결과로 같은 판단을 한다.

첫 예제는 이 웨비나의 교사 청중에 맞춘 **수업 시작 질문 영상**이다. 원본 PDF의 비유·프롬프트·장표별 문장을 옮기지 않는다. 먼저 결과를 경험하고 이후 파트에서 그 결과를 개선할 도구를 배운다. 첫 요청부터 모션 전문 용어·복잡한 설계 파일을 요구하지 않는다.

## 6장 전개

| 전체 장 | 시간 | 화면 제목 제안 | 화면·강사 진행 | 참가자의 행동 |
|---:|---:|---|---|---|
| 5 | 0:30 | 이 질문, 영상으로 시작해 볼까요? | 질문 3개와 확보한 10초 실제 예시 소개 | 자기 수업에서 쓸 위치를 떠올림 |
| 6 | 1:00 | 하고 싶은 일을 짧게 말해요 | 첫 프롬프트를 큰 글자로 제시하고 그대로 복사 | 입력할 문구 확인 |
| 7 | 3:00 | 첫 결과를 끝까지 재생해요 | 요청 실행 → 대기 → 실제 처음부터 끝까지 재생. 생성 상태와 재생 완료 구분 | 문구·순서 관찰 |
| 8 | 2:00 | 학생이 질문을 다 읽을 수 있나요? | 세 문구의 누락·순서·읽는 시간을 확인. 실제 결과에서 바꿀 점 하나 선택 | 바꿀 점과 이유 한 줄 기록 |
| 9 | 2:30 | 질문이 머무는 시간만 바꿔요 | 가운데 질문의 유지 시간만 1초 늘리도록 요청하고 A/B 재생 | 바뀐 조건과 유지된 조건 확인 |
| 10 | 3:00 | 내 수업 질문으로 바꿔 봐요 | 원래 예제의 가운데 문구 하나를 자기 질문으로 교체하도록 안내 | 수정 요청·실행·읽기 확인 또는 관찰 기록 |

합계 12분. 장표 7의 생성 대기는 60초 정도를 상한으로 제안한다. 완료되지 않으면 강사가 사전 생성해 둔 같은 요청의 실제 결과로 관찰하고, 진행 중인 작업을 반복 요청하지 않는다. 장표 10은 요청 작성 30초·실행/관찰 90초·확인과 다음 파트 연결 60초를 배정한다. 실습 속도는 주 도구 확정 후 리허설에서 조정한다.

## 첫 프롬프트

> 수업을 시작할 때 보여 줄 10초짜리 글자 영상을 만들어 줘. ‘오늘의 질문’, ‘왜 그렇게 생각했나요?’, ‘근거 한 가지’를 차례로 보여 줘. 검정 바탕에 주황색으로 강조하고 재생할 수 있는 미리보기로 보여 줘.

세부 좌표·이징·코드를 먼저 가르치지 않는다. 참가자는 도구가 요청을 어떻게 해석했는지 재생으로 확인한다. 결과에 오류가 있으면 실제 관찰한 오류부터 고친다. 처음부터 잘 만들어졌다면 실패한 것처럼 말하지 않고 두 번째 결과를 ‘다른 읽기 시간과의 비교’로 소개한다.

장표 8의 확인 질문은 세 개다.

1. 내가 요청한 문구 세 개가 그대로 있나요?
2. 요청한 순서대로 나오나요?
3. 마지막 글자까지 읽은 뒤 다음 화면으로 넘어가나요?

장표 9의 수정 요청:

> ‘왜 그렇게 생각했나요?’가 머무는 시간만 1초 늘려 줘. 문구·등장 순서·색상·나머지 동작은 그대로 유지해 줘. 전체 길이는 1초 늘어나도 괜찮아.

최초 결과는 10초, 수정본은 약 11초 제안이다. 총 10초를 유지하면서 다른 구간도 줄이라는 충돌 조건을 넣지 않는다. 정확한 길이는 실제 재생·시간 정보로 확인한다. 문구 오류가 있다면 이 요청 대신 오류 한 가지를 수정하고 실제로 수정한 조건을 기록한다.

장표 10의 개인화 요청 예시:

> 가운데 질문만 ‘두 그림에서 달라진 점은?’으로 바꿔 줘. 나머지 문구·순서·색·움직임은 유지해 줘.

참가자는 자기 교과의 질문 한 문장으로 바꾼다. 예제의 이미지·캐릭터·음악을 추가하는 과제는 넣지 않는다. 문구가 길어 읽기 어려워지면 ‘문장을 줄이기’와 ‘유지 시간 늘리기’ 중 한 가지를 선택한다.

## 화면과 자료

검정 바탕, 흰 본문, 주황 `#FF9228` 핵심어, 우측 상단 노션톡 원본 로고, 기존 NotionTalk 푸터를 사용한다. 기능적 장표 유형은 전환 → 요청 → 실제 시연 → 재생 점검 → 전후 비교 → 내 질문 적용으로 유지한다. 도형·배치는 자체 설계한 목표 템플릿에 고정한다. 기존 PDF 추출 배경·도형·도구 로고는 이용 근거가 확인되기 전 사용하지 않는다. 새로 만들었다는 사실만으로 G10 검토를 생략하지 않는다.

이번 파트의 영상은 글자 중심이므로 세 캐릭터를 장식으로 반복하지 않는다. 표지의 캐릭터 일관성 기준은 전체 강의 계획에 유지한다. 소리 없이도 질문의 순서를 이해할 수 있게 만들고, 우선 음원 없이 제작할 것을 제안한다.

| 준비할 자료 | 현재 상태 | 제작·검증 기준 |
|---|---|---|
| 주 실습 도구·입력 위치 | 두 앱의 강사 환경 확인 | 참가자 환경·수업에서 중심으로 사용할 앱은 리허설 후 결정 |
| V1 최초/수정 결과 | 실제 실행·캡처 확보 | Codex MP4 3종, Claude 10초/11초 HTML 실제 재생 화면. 배포용 Claude 파일은 미확인 |
| 시작 파일·관찰용 완성본 | 미제작 | 계정 미준비자도 비교·수정 판단에 참여 가능 |
| 상세 계획·복사할 프롬프트 | 이 문서의 제안 | 제작 시 실습 자산 목록 등록과 G10 검토 |
| 단계별 보조 장표 | 검토용 12장 제작 | 실제 UI 원본과 PowerPoint 크롭·설명. 전체 강의 제작·디자인·G10 승인과 구분 |

강의에서 중심으로 사용할 환경은 참가자 여건과 리허설로 정하고 다른 환경의 실제 조작 자료도 제공한다. 이번 실습에서 Codex MP4는 확보했지만 제품 전체의 기능·무료 범위나 Claude MP4 내보내기 성공으로 확대하지 않는다. 배포할 파일은 해당 형식으로 별도 저장·재생 검증한다. Claude는 시간 변경에 맞춰 진행 막대의 두 번째 구간도 조정했다고 설명했다. 요청한 한 조건이 다른 표시와 연동될 수 있으므로 결과를 직접 비교한다.

## 다음 파트 연결

“말로 요청해 첫 영상은 만들었어요. 이번에는 원하는 화면 분위기를 더 정확히 전하려면 무엇을 함께 보여 주면 좋을까요?”

Part 2에서는 이용 근거가 확인된 자체 제작 레퍼런스로 방향을 전달한다. 원본 강사의 사례를 재현하는 실습으로 이어 가지 않는다. Part 3에서 오늘 발견한 읽기 시간·등장 순서 문제에 필요한 모션 용어를 붙이고, Part 4에서 조건을 문서로 정리한다.
